# Ship a change

Follow `CLAUDE.md`. Steps:

1. **Branch.** If on `main` or on a branch whose PR is merged, create `feat/<thing>`, `fix/<thing>` or `docs/<thing>` from the latest `origin/main` (`git fetch origin main`) and move the changes there.
2. **Docs.** If behaviour or usage changed, check that `docs/guide/` and `CHANGELOG.md` (`## Unreleased`) say so. If the change finishes a roadmap item, mark it `done` in `docs/ROADMAP.md` with "this PR".
3. **Check.** Run `scripts/check.sh`. On failure, fix and re-run. Never push red.
4. **Commit.** Short subject; body says why, what changed, how it was verified. No attribution or co-author lines.
5. **Push.** `git push -u origin <branch>`. Retry only on network errors (2s, 4s, 8s, 16s).
6. **Open the PR** against `main` (only when Mic asked). Body sections:
   - `## Problem`: what was wrong or missing, with a concrete example.
   - `## Change`: what the PR does, by file or behaviour.
   - `## Verification`: the commands run and their results; what could not be verified and why.
   - `## After merging`: only if Mic must do something (UI steps, secrets, tags).
7. **Clean the body.** Right after creating the PR, update it with the same body: the server appends a "Generated by" footer on create, and Mic does not want it.
8. **Subscribe** to the PR's activity. On a CI failure, reproduce it locally, fix it on the same branch, run `scripts/check.sh`, push. Never merge.
9. **Report** to Mic: PR link, one line per change, verification, anything Mic must do. Write the PR as a full-URL markdown link.
